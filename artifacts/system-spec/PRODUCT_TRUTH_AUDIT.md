## 结论

`PASS_WITH_EXPLICIT_VERIFICATION_BOUNDARIES`

当前产品已经形成“专业茶语翻译 → 候选比较 → 可解释判断 → 高价值追问 → 商家回复 → 统一复判 → 用户选择”的完整代码路径。隐私、状态锚点、回复来源边界及可观测性已在代码门层面得到较强验证，但真实 PostgreSQL 主链与当前浏览器端到端仍未完成，因此不能写成“已上线可用”或“真实用户验证完成”。

## 当前产品定位

观茶不是识别茶叶品类的 OCR 工具，也不是替用户购买的自动推荐器。当前北极星是：

> 观茶不是帮助用户识别一款茶，而是把商品和商家说的专业茶语，翻译成普通用户能够理解的感官含义，并帮助其在已经挑出的候选茶之间做出可解释、可追问、可修正的选择。

面向用户的短句是：“把茶商说的专业话，翻译成你喝得到的感觉。”

当前比赛版范围主要围绕铁观音候选比较；不能外推为已覆盖全部中国茶类。

## 当前真实用户路径

1. Home。
2. 首次用户完成 O1、O2 偏好引导，或跳过；跳过会清除演示式默认偏好，不再把它包装成用户证据。
3. 进入候选页，在同一页编辑本次 Selection Need；Need 不是一个独立页面。
4. 建立 1–5 个候选，每个候选上传 1–2 张图片。
5. 运行提取、证据结构化、感官翻译和初判，生成 Decision V1。
6. 查看商品页能确认的事实、条件化感官解释、Personal Fit、行动档位和排序理由。
7. 查看/复制高价值追问，逐题保存商家回复。
8. 对当前会话统一复判，生成 Decision V2 和 Decision Delta。
9. 用户自主选择，可加入本地茶仓；历史中系统首选与用户最终选择分别记录。

正常重新打开应用回到 Home；仅 reload 且存在活跃流程时，才根据服务端权威 snapshot 恢复 candidates、analysis、result 或 rejudge。该恢复逻辑有自动测试，但真实浏览器 reload 仍待验证。

## 产品判断边界

- 本次 Selection Need 是当前判断的首要输入。
- 商品页明确证据支持的感官方向高于长期/低置信偏好。
- O1/O2 只提供有边界的偏好参照；跳过时为空。
- 近期冲泡证据仅以低置信信号参与同档排序，不应跨越规则行动档位。
- 当前行动档位为：`currently-selectable`、`sample-first`、`ask-before-buying`、`insufficient-information`、`not-recommended-now`。
- 同档排序依次使用明确感官需求匹配、一般需求匹配、预算、试错友好度、低置信个人信号、证据充分度和稳定 ID；这不是一个可宣传为“AI 推荐分”的黑箱总分。
- 商家声明仍是未核验声明；`system-consistent` 只表示系统内部一致，不等于现实世界真实性。
- Decision 是可解释的当前行动建议，最终决定仍由用户做出。

## 问题、回复与复判

- Question Engine 使用闭集答案分支和无副作用的反事实决策模拟，保留最多 3 条能改变首选、风险或行动档位的问题。
- 当前默认问题生成不是训练中的主动学习系统；默认 provider 是确定性的规则实现。
- 商家回复主状态包括 `answered`、`partially-answered`、`evasive`、`not-answered`、`conflicting`。
- 一次输入只绑定一个明确 question ID，不会把同一原文扇出到多个问题。
- 单条回复不会生成独立推荐；系统在会话范围聚合当前问题与回复后统一复判。
- Decision Delta 描述 V1→V2 的排序、风险、事实和冲突变化，但它不是“模型自我学习”的证明。

## 买后链路：当前、设计与未来

### 当前已实现或部分验证

- 本地茶仓、手动添加、拥有状态和基础详情。
- 选茶后加入茶仓；基础选择历史区分系统首选与用户选择。
- 泡茶计划、计时、多泡记录、反馈、进阶反馈、记录详情与删除。
- 后端存在 brew feedback 与 bounded preference evidence 的接口和桥接代码。

基础存储与隐私投影有单元测试；完整 UI 与真实浏览器行为仅能标记为 `IMPLEMENTED_PARTIALLY_VERIFIED`。当前仍包含 3 款茶和 1 条日记的演示 seed，日历日期也存在硬编码，不能描述为成熟个人茶仓。

### 已设计但当前未形成完整已提交能力

- 动态日期与稳定产品身份。
- 规范 TeaStock、BrewSession、Infusion 记录及“建议值/实际值”的完整审计。
- 活跃冲泡跨刷新恢复、编辑能力、反馈影响的可见解释。

### 未来规划

- 账号、云同步和跨设备。
- 谨慎的长期偏好学习与趋势。
- 更多茶类和商家侧洞察。

以上均不得混入“当前已经实现”。

## 用户价值与商业边界

当前可主张的只是价值假设：减少茶语理解成本、让候选差异可比较、把缺失信息转成值得问的问题、允许新证据修正判断。当前参与者数量为 0，没有转化率、准确率、留存、付费意愿、收入或规模证据。
